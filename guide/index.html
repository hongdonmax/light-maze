STEP 3 · VIBE CODINGAI에게 이렇게 말했어요

Claude·ChatGPT·Gemini 어느 AI든 같은 순서로 쓰면 됩니다. 한 번에 다 시키지 말고 기획 → 엔진 → 데이터 → 화면 → 퀴즈 → 학습지 순서로 쪼개서 요청하는 것이 핵심입니다.

① 기획서→② 광선 엔진→③ 스테이지 데이터 + 자동 검증→④ 화면·조작·소리→⑤ 입장퀴즈→⑥ 학습지→⑦ 다듬기
① 기획서 프롬프트너는 초등 과학 교사이자 교육용 게임 기획자야. 2022 개정 과학 5학년 1학기 '2. 빛의 성질' 단원(성취기준 [6과02-01] 물체를 보기 위해 빛이 필요함, [6과02-02] 빛의 직진·반사·굴절, [6과02-03] 거울과 렌즈의 쓰임새)을 배우는 웹 퍼즐 게임을 기획해 줘. - 장르: 레이저를 거울·물·렌즈로 꺾어 크리스탈에 닿게 하는 퍼즐 - 아래 지도서 12차시 흐름을 따라 월드 5개, 스테이지 15개로 구성 - 스테이지마다: 학습 목표, 배치(16x10 격자 좌표), 정답 배치, 힌트, 클리어 후 보여줄 개념 카드 문구 - 지도서 오개념 '눈에서 빛이 나가서 물체가 보인다'를 다루는 스테이지 포함 - 굴절 법칙(숫자)은 다루지 말고 현상 중심으로 (여기에 지도서 단원 지도 계획 표를 붙여 넣기)
② 광선 추적 엔진js/engine.js 파일을 만들어 줘. 960x600 보드(60px 격자 16x10)에서 광원에서 나온 광선을 추적하는 함수야. - 벽·바위: 빛을 막음 / 평면거울(선분, 회전 가능): 입사각=반사각으로 반사 - 물(굴절률 1.33)·유리(1.5) 사각형: 경계에서 스넬의 법칙으로 굴절, 안에서 나올 때도 굴절 - 얇은 렌즈: 볼록은 빛을 초점으로 모으고 오목은 퍼뜨림 - 크리스탈(목표)은 빛을 통과시키고 몇 번 맞았는지 셈, 박쥐(함정)에 닿으면 실패 - 손전등 모드(부채꼴로 여러 광선), 3줄기 레이저 모드 - trace(objects)와 evaluate(level, trace) 두 함수를 window.LightEngine으로 내보내 줘
③ 스테이지 데이터 + 자동 검증 (중요!)기획서의 15개 스테이지를 js/levels.js에 데이터로 옮겨 줘(벽, 광원, 크리스탈, 물, 박쥐, 부품 상자 개수, 정답 배치). 그리고 node로 실행하는 verify_levels.js를 만들어서, 각 스테이지에 정답 배치를 넣었을 때 정말 클리어되는지, 처음 상태로는 클리어되지 않는지 자동으로 검사해 줘. 안 풀리는 스테이지는 벽 위치나 크리스탈 크기를 바꿔서 고쳐 줘.
💡 AI가 만든 퍼즐은 풀리지 않는 스테이지가 섞여 있기 쉽습니다. “정답으로 정말 깨지는지 검사하는 코드”를 같이 만들게 하면 아이들 앞에서 당황할 일이 없습니다. 빛의 미로도 첫 검사에서 3개(1-3·2-3·5-1)가 정답으로도 안 풀렸고, 3-4 배치까지 모두 4개 스테이지를 이 검사로 고쳤습니다.
④ 화면 · 조작 · 소리index.html과 css, js/game.js를 만들어 줘. - 타이틀: 키아트 배경(assets/keyart.jpg), 주인공 루미 이미지, '모험 시작/가상 실험실/입장 퀴즈/놀이 방법' 버튼 - 월드맵: 월드별 카드와 스테이지 버튼(앞 스테이지를 깨야 열림, 선생님 코드로 전체 열기) - 게임: 왼쪽 부품 상자에서 거울·렌즈·바위를 끌어다 격자에 놓기, 클릭하면 회전 손잡이, Q/E로 15° 회전 - 루미가 말풍선으로 스테이지 설명과 힌트를 말해 줌 - 클리어하면 부품 수에 따라 별 1~3개, 개념 카드 획득, 전부 깨면 수료증 - 태블릿 터치로도 되게, 효과음은 Web Audio로 직접 만들어 줘(파일 없이)
⑤ 입장퀴즈quiz/index.html을 만들어 줘. 빛의 성질 단원 문항 13개(문항, 보기 4개, 정답, 해설)를 은행으로 두고 매번 10문항을 무작위로 내. 고르면 바로 정답/오답과 해설을 보여 주고, 10문항 중 7문항 이상 맞히면 '게임 입장하기' 버튼이 열리게 해 줘. 결과 화면에 틀린 문항 복습 목록도.
⑥ 탐구 활동지worksheet/index.html에 A4 2쪽 인쇄용 활동지를 만들어 줘. 1쪽: 게임 전 예상, 스테이지별 탐구 기록표. 2쪽: 빈칸 개념 정리, 생활 속 직진·반사·굴절 예, 거울·렌즈 쓰임새 연결, 거울이나 렌즈를 이용한 장치 설계 칸, '내가 빛이라면' 과학 글쓰기. 인쇄 버튼 포함.
⑦ 다듬기 요청은 이렇게(스크린샷 첨부) 3-3 스테이지에서 정답 각도 범위가 1도밖에 안 돼서 아이들이 맞추기 어려워. 크리스탈 위치나 크기를 바꿔서 정답 범위가 4도 이상 되게 하고, 똑바로 겨누면 빗나가게(굴절을 느끼도록) 해 줘. 바꾼 뒤 verify_levels.js로 다시 검사해 줘.

STEP 4 · IMAGESChatGPT로 '살아 있는' 그림 만들기

모든 그림을 한 대화방 안에서 이어서 요청했습니다. 그래야 같은 화풍·같은 캐릭터가 유지됩니다. 첫 요청에 스타일을 자세히 적고, 다음부터는 “앞서와 같은 스타일”이라고만 하면 됩니다.

🎨 키아트(메인 포스터)게임 키아트(메인 포스터) 그림을 그려줘. 스타일: 픽사+일본 애니 느낌의 생생하고 귀여운 3D 애니메이션 스타일, 상품 캐릭터처럼 윤기 나고 선명한 색감, 영화 포스터 같은 극적인 구도. 주인공: 10살 한국 초등학생 탐험가 '루미'(짧은 갈색 머리, 노란 탐험가 조끼, 헤드램프, 큰 눈, 신난 표정, 손에 빛나는 레이저 손전등). 배경: 신비로운 '빛의 미로' 크리스탈 동굴. 붉은 레이저 빔이 여러 개의 평면거울에 반사되며 꺾이고, 투명한 물 웅덩이를 지나며 굴절되고, 커다란 볼록 렌즈를 통과해 한 점으로 모여 거대한 크리스탈을 환하게 밝히는 장면. 주인공 옆에는 반딧불처럼 빛나는 작은 빛의 요정 '반디'가 떠 있음. 깊은 남색·보라색 어둠 속에 네온처럼 빛나는 광선과 반짝이는 입자. 글자나 텍스트는 절대 넣지 말 것. 가로 16:9 비율.
🧒 캐릭터(배경 제거용)같은 주인공 '루미'를 게임 UI용 캐릭터 그림으로 그려줘. 전신, 정면을 보고 서서 한 손에 빛나는 레이저 손전등을 들고 다른 손은 엄지척, 밝게 웃는 표정. 앞서 그린 생김새를 그대로 유지. 배경은 아무 무늬 없는 완전한 단색 밝은 초록색(#00FF00) 크로마키 배경, 그림자 없음, 캐릭터 전체가 잘리지 않게 여백을 두고. 글자 없음. 세로 2:3 비율.
🏞️ 스테이지 배경 (월드마다 제목만 바꿔서)이번엔 게임 스테이지 배경 그림(캐릭터 없음, 글자 없음)을 그려줘. 제목: '굴절의 호수'. 맑고 투명한 청록빛 크리스탈 호수. 공기에서 수면으로 비스듬히 들어가는 붉은 레이저 빔이 수면 경계에서 꺾여 물속 크리스탈을 비추는 장면, 물에 반쯤 잠겨 꺾여 보이는 나무 막대. 앞서와 같은 스타일. 화면 가운데는 비교적 비어 있게(게임 보드가 올라갈 자리). 가로 16:9.
💎 아이템 스프라이트 시트 (12개를 한 장에)게임 아이템 스프라이트 시트를 그려줘. 앞서와 같은 픽사+애니 3D 스타일. 배경은 아무 무늬 없는 완전한 단색 밝은 초록색(#00FF00). 4열 x 3행 격자로 12개를 간격을 넓게 두고 각 칸 가운데에 하나씩, 서로 겹치지 않게, 그림자 없이, 글자 없이. 1행: 빛을 못 받은 어두운 보라색 크리스탈 / 환하게 빛나는 황금빛 크리스탈 / 잠든 귀여운 박쥐 / 깜짝 놀라 눈을 크게 뜬 박쥐. 2행: 닫힌 보물상자 / 열려서 빛나는 보물상자 / 옆에서 본 레이저 발사기 / 옆에서 본 손전등. 3행: 둥근 바위 / 이끼 낀 돌기둥 / 빛나는 물고기 / 별 모양 배지. 정사각형 1:1.
🟩 왜 초록 배경? 캐릭터·아이템은 게임 화면 위에 올려야 해서 배경이 투명해야 합니다. 초록 단색으로 받으면 배경을 깔끔하게 지울 수 있어요. 지우는 방법(쉬운 순서): ① 처음부터 ChatGPT에게 “배경을 투명하게(PNG) 해 줘”라고 요청해 내려받기, ② 캔바 편집 → 배경 제거 후 PNG(투명 배경)로 다운로드, ③ 파워포인트 그림 서식 → 배경 제거 후 ‘그림으로 저장’, ④ AI에게 “초록색을 투명하게 바꾸는 파이썬 코드”를 받아 실행(빛의 미로는 이 방법). 테두리에 초록 기운이 남으면 “초록 번짐(despill)도 없애 줘”라고 하세요.

STEP 5 · GITHUB PAGES링크 하나로 교실에 배포하기

명령어 없이 웹 화면만으로 할 수 있습니다. 저장소 이름이 곧 주소가 됩니다: https://아이디.github.io/저장소이름/

  1. github.com 로그인 — 계정이 없으면 Sign up으로 가입(학교 이메일 추천).
  2. 새 저장소 만들기 — 오른쪽 위 ＋ → New repository → 이름 light-maze → Public 선택 → Create repository.
  3. 파일 올리기 — 빈 저장소 화면의 uploading an existing file 링크(파일이 이미 있으면 Add file → Upload files) → light-maze 폴더 안의 파일과 폴더(index.html, css, js, assets, quiz, worksheet, guide)를 전부 끌어다 놓기 → 아래 Commit changes. 웹 업로드는 파일 하나당 25MB, 한 번에 100개까지예요.(넘으면 폴더를 나눠서 두 번 올리기)
  4. Pages 켜기 — 저장소 위쪽 Settings → 왼쪽 Pages → Build and deployment의 Branch를 main / (root)로 고르고 Save.
  5. 1~2분 기다리기 — Pages 화면 맨 위에 “Your site is live at …” 주소가 뜹니다. 예: https://hongdonedu.github.io/light-maze/
  6. 아카이브도 같은 방법 — vibe-archive 저장소를 만들어 아카이브 폴더 안의 파일을 올리고 Pages를 켭니다. 두 저장소가 같은 계정에 있으면 아카이브의 ‘프로그램 시작’ 버튼이 빛의 미로로 바로 연결됩니다.
  7. 고칠 때 — 바뀐 파일만 같은 자리에 다시 업로드(Add file → Upload files)하면 덮어써지고 1~2분 뒤 자동으로 반영됩니다.
⚠️ 저장소가 Public이면 누구나 코드를 볼 수 있습니다. 학생 이름·사진·개인정보가 담긴 파일, API 키가 들어 있는 파일은 올리지 마세요.
📄 첫 화면 파일 이름은 꼭 index.html이어야 주소만으로 열립니다. 윈도우는 확장자를 숨겨서 index.html.html처럼 저장되는 실수가 잦아요. 탐색기 보기 → 파일 확장명을 켜고 확인하세요.
